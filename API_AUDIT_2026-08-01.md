# Backend API Audit — 2026-08-01

Scope: `apps/api/src/routes/*`, `apps/api/src/services/ccxtSync.ts`, `apps/api/src/validators/*`
Focus: auth coverage, raw SQL, N+1 patterns, input validation, unbounded queries.

> **Status: All 7 findings FIXED (2026-08-01).** Typecheck (`tsc --noEmit`) passes. See "Resolution" note under each finding.

## 🔴 Critical

### 1. Unauthenticated AI blog generation — `routes/aiAutomation.ts:7`
`POST /api/internal/ai/blog/generate` has **no auth middleware and no shared-secret check**. Anyone on the internet can trigger paid AI article generation with an arbitrary `authorId`, draining your AI API budget and spamming the blog.

**Fix:** Require an internal secret header (e.g. `x-internal-key` compared against `process.env.INTERNAL_API_KEY` with timing-safe compare) or restrict to admin via `authenticate, requireAdmin`. Add a rate limit.

**✅ Resolved:** Endpoint now requires `x-cron-secret` header matched (timing-safe) against `AI_AUTOMATION_CRON_SECRET` (returns 503 if unset, 401 if wrong) and is rate-limited to 10/hour per IP. Env var documented in `.env.example`.

### 2. Unauthenticated market-data proxy with unbounded `limit` — `routes/marketData.ts:159`
`GET /api/market-data/history` is public and proxies **paid TwelveData API calls**. Two issues:
- `limit` is `parseInt(req.query.limit || '10000')` with **no max cap** — `?limit=10000000` forces repeated upstream pagination (up to `limit/5000 + 1` requests per call).
- No rate limiting. On cache miss, each request burns upstream quota; an attacker can cycle `symbol`/`timeframe` combos to bypass the DB cache entirely.

**Fix:** Clamp `limit` (e.g. `Math.min(limit, 10000)`), add `rateLimit`, and consider requiring auth (or at least a stricter anonymous limiter).

**✅ Resolved:** `limit` is clamped to `MAX_CANDLE_LIMIT = 10000` (invalid values fall back to the cap) and the route is rate-limited to 30 req/min per IP.

## 🟠 High

### 3. SMS OTP endpoints lack IP-based rate limiting — `routes/auth.ts:240, ~380`
`/otp/send` rate-limits **per phone number** (2-min DB check) but not per IP. An attacker rotating phone numbers can send unlimited SMS messages at your expense. `/otp/register` has no rate limit at all (unlike `/otp/verify`, which has `rateLimit(2min, 5)`).

**Fix:** Add `rateLimit` middleware (IP-based) to `/otp/send` and `/otp/register`, matching the pattern already used for `/otp/verify`.

**✅ Resolved:** `/otp/send` now limited to 10/hour per IP (per-phone 2-min check retained); `/otp/register` limited to 5/hour per IP.

### 4. N+1 / sequential inserts in crypto sync — `services/ccxtSync.ts:146-226`
The trade-processing loop awaits `prisma.trade.create` + two `prisma.execution.create` calls **sequentially per trade**. Syncing 500 trades = ~1500 round-trips, one at a time.

**Fix:** Collect new trades first, then use `prisma.trade.createMany` (skipDuplicates) and a single `execution.createMany` with resolved trade IDs, or at minimum wrap batches in `prisma.$transaction([...])` to pipeline them.

**✅ Resolved:** New trades are collected, inserted with one `trade.createMany({ skipDuplicates: true })`, IDs resolved via a single `findMany`, and executions inserted with one `execution.createMany`. ~1500 sequential round-trips → 3 queries.

### 5. Unbounded export query — `routes/tradeExport.ts:155`
`prisma.trade.findMany` has **no `take` limit**. A PRO user with a very large history (or a compromised PRO token) can load the entire table into memory and build XLSX/PDF synchronously, blocking the event loop.

**Fix:** Add a hard cap (e.g. `take: 50_000`) and/or stream with a cursor. Consider a per-user export rate limit.

**✅ Resolved:** Export query now hard-capped with `take: 50_000`.

## 🟡 Medium

### 6. No input validation on backtest session creation — `routes/backtest.ts:30`
`POST /api/backtest` reads `tradeLog` and `equityCurve` straight from the body into JSON columns with **no zod schema and no size cap**. A user can store arbitrarily large payloads (DB bloat) and create unlimited sessions (GET only returns 50, but POST has no per-user count limit).

**Fix:** Add a zod schema (numeric fields, string lengths), cap array sizes (e.g. `z.array(...).max(10_000)`), and enforce a per-user session cap (delete oldest or reject beyond N).

**✅ Resolved:** `createSessionSchema` (zod) validates all fields with length/range caps (`tradeLog`/`equityCurve` capped at 10k entries), and a per-user cap of 50 sessions is enforced (oldest auto-deleted).

### 7. Admin endpoints without pagination — `routes/admin.ts:52`
`GET /api/admin/users` does `user.findMany` with a nested `subscriptions` include and **no `take`/cursor**. Fine today, but it will degrade linearly with user growth.

**Fix:** Add cursor-based pagination (`take` + `skip` or cursor) and a search filter.

**✅ Resolved:** `GET /api/admin/users` now supports `page`/`pageSize` (max 100) + `search` (email/name/phone), returns `{ data, pagination: { page, pageSize, total, totalPages } }`. ⚠️ Response shape changed from a bare array — update the admin frontend accordingly.

### 8. Revenue sum loads all receipts into memory — `routes/admin.ts:24-28`
`manualReceipt.findMany({ select: { amount: true } })` + JS `reduce` to compute total revenue.

**Fix:** Use `prisma.manualReceipt.aggregate({ _sum: { amount: true }, where: { status: 'APPROVED' } })`.

**✅ Resolved:** Revenue now computed via `manualReceipt.aggregate({ _sum: { amount: true } })` in the database.

## ✅ What's already good

- **No raw SQL** — zero `$queryRaw` / `$executeRaw` usage; all queries go through Prisma (parameterized).
- **Payments are transactional** — checkout/verify flows wrap session deletion, subscription swap, user update, and discount-code `increment` inside `prisma.$transaction`, so discount redemption can't be double-spent.
- **CSV injection is handled** — `sanitizeCsvCell` prefixes formula-leading characters in `tradeExport.ts`.
- **Zod validators exist for trades** (`validators/trade.ts`) with sensible length/positivity constraints.
- **Auth middleware is consistently applied** — admin routers use `router.use(authenticate, requireAdmin)`; user routes use `authenticate` per-route. Ownership checks are present (e.g. `backtest.ts:81` verifies `session.user_id !== userId`).
- **OTP verify is rate-limited** and codes are deleted after use.
- **Market-data route degrades gracefully** — serves stale cache when upstream fails.
